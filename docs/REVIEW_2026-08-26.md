## 3. 已核验的强项（证据优先）

1. **密钥静态安全路径是健全的（D-011）**：`SecretStore` 只写 base64 密文，`mode 0o600`（secrets.ts:46-47）；`createSafeStorageCipher` **无明文兜底**，加密不可用即抛错（safe-storage-cipher.ts:10-13）；`ProviderProfile` 无 apiKey 字段，密钥只经 `DEEPSEEK_API_KEY` env 注入子进程（dsh.ts:37-40），`writeDshProviderSettings` 从不写入 key（dsh-settings.ts:27-30）。已有测试证明磁盘无明文（secrets.test.ts:38-44）。
2. **CSP 分层正确**：app 自身页面严格 CSP（`script-src 'self'`、无 `'unsafe-eval'`、object/base/form/frame 全锁）；宽松的 `'unsafe-inline' 'unsafe-eval'` 只施加在 DSH loopback origin（window.ts:60-67）。（security.test.ts:120-133 强制）。
3. **渲染进程加固真实**：`contextIsolation/sandbox/webSecurity` 全开；preload 只暴露冻结的 37 个 `invoke` 通道（无 send/on/sendSync）；权限请求全部拒绝；渲染层无 innerHTML/eval（grep 干净）。
4. **无不可信 loadURL/executeJavaScript**：所有 loadURL 都是 supervisor 返回的 loopback URL 或 app 自身 `index.html`；executeJavaScript 仅 smoke 且为静态字符串。
5. **DSH 子进程 loopback-only + 随机端口 + 无 shell**（dsh.ts:53-58，supervisor.ts:166-172）。
6. **会话操作路径安全**：`^session-[0-9a-f-]+$` + resolve 包含性校验 + Dirent 不跟随符号链接（session-store.ts:58-96）。
7. **供应链卫生**：DSH 精确锁定 `0.1.0-rc.6`；CI `--frozen-lockfile`；release 运行时安装 `--ignore-scripts`（无安装期任意脚本）；SBOM 生成并随 release 上传。
8. **测试质量真实**：supervisor 用 fake-dsh fixture 真进程模拟崩溃/健康/重启；persistence.test.ts 真实拉起 DSH headless 对 mock provider 做端到端会话持久化；store 测试有临时目录隔离 + 损坏文件负例。

## 5. 残项风险与边界（诚实声明）

1. **DSH 运行时未 vendor 在本仓库**（release 时才下载），其 SPA/CSP/导航/API 校验行为无法在本仓库内验证（R-32）——R-01/R-11/F2 的最终修复需对锁定版本实测。
